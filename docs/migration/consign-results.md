# Consign migration checkpoint

Consign is the twenty-fifth live Spring Modulith business module. Its existing address at port 16111 and the browser gateway at port 8080 route to the shared host and return `X-Consign-Backend: module`. The compatibility router can switch only Consign back to its legacy service. The module uses the published `ConsignPriceOperations` API in process for quotes; its Spring Modulith boundary allows only the ConsignPrice dependency.

The deployed Consign JAR uses MongoDB, despite JPA annotations in the checked-out source. The module reads and writes the existing `ts.consign_record` collection. Six existing records were backed up to ignored `deployment/migration/.state/backups/consign.archive` before cutover. The original service remains available for rollback, with an independent write gate preventing the inactive implementation from writing.

The isolated candidate passed 25 comparisons, including existing and missing reads, ADMIN/USER access, creation, same-weight updates and weight-change repricing. Maven tests passed, including Spring Modulith boundary verification. The live 25-module checkpoint passed. A rollback rehearsal created a disposable record on the module, read and updated it on legacy, verified the inactive module rejected writes, and read the update after return to the module. The synthetic record was removed. A separate port 8080 test submitted the UI's `PUT /api/v1/consignservice/consigns`, confirmed `X-Consign-Backend: module`, read the record back, and removed it.

For a browser check, open **Order List → Consign** on an eligible order and submit the consignment form. In DevTools Network, inspect the `PUT /api/v1/consignservice/consigns` response for HTTP 200 and `X-Consign-Backend: module`. **Consign List** reads the resulting shipment. The pricing call is now local inside the Modulith, so the browser will not show a separate ConsignPrice request for this path. A successful HTTP response or backend header alone does not establish every business use case; the automated candidate and rollback checks cover the specific cases above.

Checks: `python docs/migration/verify_checkpoint.py`, `python docs/migration/verify_consign_rollback.py`, and `python docs/migration/verify_consign_ui.py`. The deployed Food Map service has since been migrated as the next available provider; see the [Food Map checkpoint](foodmap-results.md). WaitOrder remains pending because its service and database are absent.
