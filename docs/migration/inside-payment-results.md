# Inside Payment migration checkpoint

Inside Payment is the twentieth Spring Modulith business module. It retains `ts-inside-payment-service:18673` through a reversible compatibility proxy and uses the deployed service's MongoDB collections `ts.payment` and `ts.addMoney`. It calls published Orders, OrderOther and Payment module APIs. The original Inside Payment container remains available for rollback; `X-InsidePayment-Backend: module` identifies the active proxy target.

The isolated candidate used separate wallet, Orders, OrderOther and outside Payment databases. The final 51-check comparison covered existing payment/account/money reads; account creation and duplicate rejection; add money and drawback; wallet payment; outside payment; both order types; duplicate payment; pay difference; and the Order List request shape that omits `userId`. Synthetic orders and user IDs were unique. Both live collections were backed up under ignored `deployment/migration/.state/backups/` before cutover.

The rollback rehearsal switched only Inside Payment to legacy, confirmed the inactive module rejected writes with HTTP 503, paid a synthetic ticket, and checked wallet and outside Payment records. After returning to module mode, it verified the legacy record remained readable and repeated a synthetic payment through the module. The full checkpoint and Maven test suite passed. A synthetic POST through browser-facing port 8080 returned HTTP 200 with `X-InsidePayment-Backend: module`, changed the order to Paid, and created an outside Payment record.

The deployed `payDifference` code discards its `BigDecimal.add` results, so its external-payment branch is unreachable. This module preserves that behavior for compatibility; correcting it requires a separate behavior change and refund/rebooking tests. Payment, wallet and order writes still span separate Mongo databases. Neither the legacy service nor the module makes those writes atomic, so failure recovery and concurrency need dedicated acceptance work before production consolidation.

To verify now, run `python docs/migration/verify_checkpoint.py`. In **Order List → Pay**, inspect the `POST /api/v1/inside_pay_service/inside_payment` response: `X-InsidePayment-Backend: module` confirms the browser-facing request reached the module. `python docs/migration/verify_inside_payment_ui.py` runs a disposable paid-order test through port 8080. For rollback, run `python docs/migration/verify_inside_payment_rollback.py`, or switch manually with `python docs/migration/hybrid_routing.py legacy insidepayment` and `python docs/migration/hybrid_routing.py module insidepayment`.
